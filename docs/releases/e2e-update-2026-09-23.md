## Review and changes

Business, financial, field and security/release reviews identified and corrected:

- Customer acceptance: legacy billable creation, commercial edits and settlement readiness now require customer acceptance from the latest inspection cycle and enforce accepted quantity/unit limits. Caller-supplied acceptance and quantity overrides cannot substitute for customer decisions. Existing decision lineage stays bound; changed decisions require controlled adjustments.
- Duplicate billing: legacy and canonical creation serialize on the production record and reject competing active base billables while preserving legitimate retries and separate coil supplements.
- Billing interoperability: customer-accepted field billables remain visible without a legacy internal-QC row. Their readiness follows current customer acceptance. New invoices and linked legacy settlement/invoice items recheck acceptance; explicit invoice selection rejects held, disputed, already-invoiced or unavailable items.
- Payments: external recording rejects disputed/retired payables. Item editing and approval recheck amounts against their source ceilings under the existing explicit override policy.
- Field corrections: a retry after a lost response returns the prior result for the same correction, without duplicate revisions; mismatched correction identifiers fail. Accepted zero is displayed as zero in production PDF output.
- Maps: authenticated PDF preview replaces a placeholder. Page/zoom controls and work-zone page/zoom bookmarks work; selected-assignment authorization controls file access. Temporary browser file URLs are revoked when changing assignments or leaving the screen.
- Accessibility: login supports keyboard form submission, required-field validation, password managers and announced feedback. Crew participation controls identify each worker and expose the selected state and saved feedback.
- Account onboarding: existing profiles no longer hide eligible newly identified organizations. Saved profiles take precedence. Unauthorized create links are hidden; instructions distinguish account readiness from crew and work-order approval.
- Release safety: registered smoke checks are included; migration checks use the actual shipped manifest. Source scans skip generated/dependency trees. Deployment rejects dirty releases and active legacy services, stops staging writers before migrations, and leaves services stopped on failed activation rather than silently restarting incompatible code.
